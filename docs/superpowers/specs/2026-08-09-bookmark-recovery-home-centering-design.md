# 原收藏恢复与首页居中设计

日期：2026-08-09

状态：已批准。用户要求完全自主执行，不设置人工查看或批准门槛。

## 1. 背景与问题

目录合并后，“加载已解压”扩展的路径身份发生变化。原收藏仍可能保存在浏览器书签栏的 `Fu 导航` 文件夹中，但当前配置不会自动把该文件夹重新并入导航。截图同时显示首页搜索与六个常用卡片贴近顶部，且不足一整行的常用卡片向左堆积，右侧主区虽然数学上横向居中，视觉上仍明显失衡。

## 2. 目标

1. 在不覆盖当前配置、不删除任何现有条目的前提下，从浏览器书签树中恢复名称为 `Fu 导航` 的原收藏文件夹。
2. 对同 URL 条目去重，保留现有条目的名称、备注、标签、点击数据与稳定 ID。
3. 新旧数据都保存在名为 `Fu 导航` 的单一分组中；浏览器文件夹下任意深度的网站无损展平到该分组，匹配截图中的单组收藏体验。
4. 搜索与常用卡片组成统一首页主任务块；无可见组件时在右侧可用视口内水平、垂直居中，有组件时位于首屏上半部的光学中心。
5. 常用卡片不足整行时最后一行居中，6/8 列设置、移动端 4 列与 1024×768 首屏要求继续成立。

## 3. 非目标

- 不读取或修改 Chrome profile 文件。
- 不静默申请 `bookmarks` 权限；只有权限已经存在时才自动恢复，未授权时保留现有显式导入入口。
- 不开启浏览器书签双向同步，不把导航配置反向覆盖到浏览器书签。
- 不改变侧栏、分组页、文件夹页、设置、popup 的信息架构或设计 token。

## 4. 数据恢复设计

新增独立纯函数模块 `shared/bookmark-recovery.js`：

- `findLargestNamedFolder(tree, title)` 递归查找同名文件夹，按后代网站数量选择数据最多的一份。
- `mergeBookmarkFolder(config, folder, options)` 克隆配置，把文件夹全部后代网站展平后并入同名分组。
- URL 去重使用 `normalizeUrl(url, 'strict')`；空 URL 和非网站节点不生成条目。
- 已存在 URL 不修改，新增条目生成稳定 ID，并返回 `{ config, added, duplicates, total, groupId }`。

`Core.recoverOriginalBookmarks()` 只在以下条件同时满足时运行：扩展环境、尚未完成本版本恢复、`bookmarks` 权限已经授予、浏览器书签 API 可用。找到数据后先保存本机恢复快照，再应用纯函数结果并落盘；无数据或无权限时不修改配置、不标记永久失败，以便以后重试。成功核对后写入 `settings.bookmarkRecoveryV326`，避免每次启动重复扫描。

## 5. 首页布局设计

设计读法：现有个人效率首页的 preserve 型定向优化，继续使用项目原生 CSS token、Lucide 图标和深浅双主题。设计参数为 `DESIGN_VARIANCE 4 / MOTION_INTENSITY 3 / VISUAL_DENSITY 4`。

`renderHome` 新增 `.fx-home-primary` 包裹搜索与常用区：

- 宽度 100%，内部水平居中。
- 无组件时占满扣除首页上下内距后的可用高度，并用 `justify-content:center` 垂直居中。
- 有组件时使用受控的首屏舞台高度，搜索和至少八个常用项仍位于 1024×768 首屏，组件接在舞台后。
- `.fx-favs` 改为可换行的居中 flex 布局；6 列、8 列、移动端 4 列分别使用确定的卡片 basis，最后一行自然居中。
- `≤760px` 继续使用顶部 72px 导航安全区，不做垂直居中，避免软键盘和抽屉遮挡。

## 6. 异常与安全

- 恢复函数只增加缺失 URL，不删除浏览器或导航中的任何内容。
- 读取失败、权限缺失、文件夹不存在均保持当前配置原样。
- 发生实际新增前保存快照；保存失败不宣称恢复成功。
- 自动恢复不会触发权限弹窗，也不会启用同步或联网。

## 7. 验收

- 单元测试覆盖多份同名文件夹择大、任意深度展平、规范化 URL 去重、保留现有元数据、幂等重放。
- 静态响应式测试覆盖主任务块、无组件垂直居中、6/8/4 列最后一行居中规则与移动端取消垂直居中。
- 真实扩展 E2E 在已授权书签边界下注入 `Fu 导航` 文件夹，确认自动恢复一次、数据不重复、现有条目不丢。
- 1024×768 与 390×844 检查无横向溢出、主操作不裁切；桌面截图几何确认主任务块中心与右侧可用视口中心误差不超过 2px（无组件场景）。
