# 壁纸按频率自动更新设计

日期：2026-08-14

状态：按用户“完全自主执行”约束直接实施。

配套计划：`docs/superpowers/plans/2026-08-14-wallpaper-refresh-scheduler-plan.md`

验收合约：`docs/superpowers/evals/2026-08-14-wallpaper-refresh-scheduler-eval.md`

## 问题

在线壁纸设置中的更新频率已被保存，但当前实现只在首页重新执行背景渲染时检查是否到期。首页持续打开时没有定时触发源；即使重新进入首页触发了到期拉取，拉取结果也不会立即应用到当前页面。因此“每 N 分钟更新”实际退化成“下次页面刷新时检查”。

## 目标行为

- 在线壁纸且更新频率大于零时，首页按 `lastFetchAt + refreshEvery` 安排下一次自动更新。
- 首页打开期间，到期后自动拉取壁纸；成功后立即显示在当前首页，并继续安排下一次更新。
- 修改更新频率后立即重新排期；改成“仅手动更新”、离开首页或关闭背景时立即取消排期。
- 拉取失败时继续显示旧壁纸，不清空缓存；下一次尝试仍使用用户选择的同一更新频率，不引入额外重试阈值。
- 继续沿用现有在线来源解析、缓存、请求竞态和手动更新逻辑，不改变收藏、工作区、时钟或壁纸来源配置。

## 方案

采用首页进程内的一次性定时器。每次成功、失败或设置变更后重新计算下一次触发时间，而不是使用固定 `setInterval`；这样能以持久化的 `lastFetchAt` 为基准，并避免刷新耗时导致累计漂移。

不采用扩展后台 `chrome.alarms`：本缺陷要求当前首页按频率更新，后台闹钟会扩大权限、服务工作线程和跨页通知范围。也不继续依赖页面加载检查，因为它无法覆盖首页长时间保持打开的核心场景。

## 边界

- 浏览器完全关闭或没有 Fu Nav 首页进程时不承诺后台下载；下次打开首页会根据持久化时间立即判断是否到期。
- 浏览器对后台标签页的计时器可能延后执行；页面恢复调度后仍按已到期状态立即更新。
- 自动刷新失败不替换现有背景，也不生成比用户频率更激进的重试行为。

## 自动验收

- 使用可控时钟验证排期、到期触发、成功重排、失败重排、取消和设置变化。
- 真实扩展组合场景验证：已到期的在线壁纸无需重载即可在当前首页被新图片替换。
- 项目全量单元、静态合约和真实扩展 E2E 均由机器命令判定。
