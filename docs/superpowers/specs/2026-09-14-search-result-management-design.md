# 搜索结果管理设计

日期：2026-09-14

状态：按用户既有“完全自主执行、无需人工批准”约束直接实施。

配套计划：`docs/superpowers/plans/2026-09-14-search-result-management-plan.md`

验收合约：`docs/superpowers/evals/2026-09-14-search-result-management-eval.md`

## 问题

首页搜索结果目前只是一组可打开的链接。找到收藏后，如果想固定到首页、调整所属收藏夹或修改名称/网址/备注/图标，必须先关闭搜索，再去侧栏定位原条目，操作链路断裂。

## 目标行为

- 有收藏结果时，结果面板头部显示用途提示、“首页”投放目标和“编辑”开关。
- 普通状态继续以点击打开为主；每条结果同时支持整行拖拽，不要求先解锁全局编辑模式。
- 拖到结果面板的“首页”目标或侧栏“首页”导航项，原网站被固定到首页常用，并追加到固定顺序末尾；键盘或点击“首页”目标时固定当前第一条结果；已固定时保持幂等，不重复 ID。
- 拖到侧栏分组，移动原网站到该分组顶层；拖到侧栏已展开文件夹，移动原网站到该文件夹。移动保持稳定 ID 与全部元数据，不复制，不改变首页固定状态。
- 搜索面板的“编辑”是局部管理态，不改变侧栏全局锁定状态。开启后每条结果显示编辑按钮，点击复用现有 `openItemEditor` 完整编辑弹窗。
- 编辑保存继续走现有稳定 ID、本机操作队列和保存逻辑；删除、分组选择、首页固定、iframe、标签、别名和图标能力均复用现有编辑器。
- 非法目标、拖回原位置和已固定首页均不制造重复数据，并给出明确反馈。
- 拖拽结束、放置完成、清空搜索或 Escape 后清理高亮和拖拽状态。

## 交互与视觉

这是现有搜索浮层的 preserve 型增强，不引入新视觉体系。结果头部继续使用 `overlay-bg`、现有边框、圆角、间距和 Lucide 图标；“首页”是紧凑投放 chip，“编辑”是 32px 以上的文字图标按钮并使用 `aria-pressed`。拖动时目标使用既有 accent/ring 高亮；结果行只在拖动和局部编辑态增加必要 affordance，不常驻堆叠操作。

移动端保留点击打开与编辑按钮；原生 HTML5 拖拽能力以桌面浏览器为验收范围，不为本轮新增触摸拖拽框架。

## 数据与错误边界

- 首页投放只修改目标条目的 `fav` 和去重后的 `favOrder`。
- 收藏夹投放只调用稳定 ID 的树移动接口，并记录现有 `edit` 本地操作以支持跨标签重放。
- 搜索结果持有条目 ID；执行动作前重新从当前配置定位，避免编辑/同步后使用游离对象。
- 任何失败均保留原位置与原数据。

## 自动验收

- 静态测试证明结果头部、编辑开关、拖拽语义、首页/分组/文件夹投放接线与可访问名称存在。
- 真实扩展 E2E 从搜索结果依次验证：拖到首页、拖到已展开文件夹、开启编辑并修改网站信息；最终 storage 中 ID 唯一、位置准确、元数据和首页固定状态保留。
- 全量 Node、静态和真实扩展 E2E 必须继续通过。
