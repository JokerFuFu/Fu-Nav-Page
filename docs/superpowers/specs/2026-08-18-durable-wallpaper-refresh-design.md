# 壁纸后台持久自动更新设计

日期：2026-08-18

状态：按用户既有“完全自主执行、无需人工批准”约束直接实施。

配套计划：`docs/superpowers/plans/2026-08-18-durable-wallpaper-refresh-plan.md`

验收合约：`docs/superpowers/evals/2026-08-18-durable-wallpaper-refresh-eval.md`

## 问题与证据

现有自动更新由新标签页 JavaScript 上下文中的一次性 `setTimeout` 驱动。用户从新标签页进入网站后，该页面通常被导航替换、关闭或由浏览器回收，计时器随之消失。真实扩展测试在没有任何 Fu Nav 页面打开时，把在线壁纸设为已过期；连续两次运行都未启动网络请求，`onlineImageId` 和 `lastFetchAt` 均保持不变。

## 目标行为

- 在线壁纸且更新频率大于零时，由 Manifest V3 Service Worker 持有唯一自动调度职责。
- 即使没有 Fu Nav 新标签页打开，更新到期后仍能拉取、写入 IndexedDB、更新独立本机运行状态并安排下一次任务。
- 浏览器启动、扩展安装/更新、配置变化和壁纸闹钟触发时都重新核对计划；已过期任务立即尝试，未过期任务创建一次性 alarm。
- 成功后以 `lastFetchAt + refreshEvery` 安排下一次；失败时保留旧图，以本次 `lastRefreshAttemptAt + refreshEvery` 再试，不产生立即重试循环。
- 外部下载开始前必须先持久化尝试时间并创建 retry alarm；即使 Worker 在网络期间被终止，仍保留下一次唤醒入口。
- 自动更新不得整份写回 `fn_config`。下载结果写入独立的 `fn_wallpaper_refresh_v1` 本机状态；提交前重新读取最新配置，只在在线模式、来源和原图片引用仍与任务快照一致时更新运行状态，迟到结果不得覆盖下载期间发生的任何用户编辑。
- 改成“仅手动更新”、关闭背景或切换到非在线背景时清除 alarm。
- 打开的首页不再持有自动刷新计时器，只显示本地缓存；Service Worker 写入配置后，现有 storage 变更流程负责让页面采用新图。
- 定时任务不得弹权限请求。内置来源或用户先前主动授权的自定义来源可以自动更新；缺少来源权限时保留旧图并按原频率再试。

## 方案选择

采用 `chrome.alarms` 的一次性 alarm，并在每次事件后从持久化配置重新计算下一次时间。它适配 MV3 Service Worker 的休眠/唤醒模型，也不会因页面销毁丢失。

不采用页面 `setTimeout`，因为它已经被真实场景证明不持久；不只做启动时补检查，因为浏览器持续运行期间仍不会按频率更新；不创建 offscreen document，因为为一个定时网络任务维持隐藏页面会扩大权限和生命周期复杂度。

## 模块边界

- `shared/wallpaper-refresh.js`：定义自动更新是否启用、基准时间、到期状态和下一次时间，并以带错误检查的独立 local key 保存最近尝试/成功和自动缓存引用。
- 根 `background.js`：把独立运行状态、`chrome.alarms` 和在线图片下载管线组合起来，执行到期任务并重排；不写整份收藏配置。
- `shared/background.js`：继续负责来源解析、下载、图片存储和页面显示；页面优先显示与当前来源匹配的自动缓存，手动换图时清理该缓存。
- `shared/storage.js` / `shared/core.js`：区分配置变更与自动壁纸运行状态变更；后者只重新应用首页背景，不触发整份配置采纳或保存。

## 自动验收

- 纯函数测试覆盖启用、到期、失败后重排、仅手动和非在线模式。
- 真实扩展测试在没有 Fu Nav 页面打开时注入已过期配置，断言 Service Worker 自动替换缓存图片并推进抓取时间。
- 同一真实扩展测试扣住网络响应，断言请求期间 retry alarm 已存在、迟到响应不会覆盖新配置、未来 alarm 能主动触发、未授权来源不会请求权限。
- 静态测试确认 `alarms` 权限和 Service Worker 接线存在，页面模块不再持有自动 timer。
- 全量单元、静态和产品 E2E 均由命令退出码判定。
