# Fu 导航 · 产品体验与可靠性升级 Product Spec

日期：2026-08-09
状态：已确认，可实施
配套计划：`docs/superpowers/plans/2026-08-09-product-experience-upgrade-plan.md`
验收合约：`eval.md`

## 1. 背景与问题

Fu 导航已经具备分组、两级文件夹、首页常用、搜索/AI Provider、命令面板、工具栏收藏、浏览器书签同步、WebDAV/Google Drive 备份、场景模式、引导、使用统计、壁纸、天气和本机 Agent 等能力，视觉系统也已经经过多轮设计收敛。

实施基线以公开仓库 3.23.1 为准。该版本已经采用 `chrome.storage.local` 唯一权威、`chrome.storage.sync` 仅作新设备引导快照、popup 通过 `fn_inbox` 增量交付操作、WebDAV 只允许显式手动恢复。后续不得重新引入后台自动拉取、整份远端覆盖本地或 add-only 合并。

当前瓶颈不是功能数量，而是产品闭环：

1. 新标签页的首要任务“一眼找到、立即打开”被大时钟和组件挤出首屏。
2. 搜索、锁定、嵌套项目等关键交互存在行为与文案不一致。
3. 配置合并、导入恢复和云备份缺乏足够的数据安全保障。
4. 首次使用会暴露演示数据、天气定位和未配置硬件失败状态，信任建立不足。
5. 数据达到数百条后，缺少批量、重复检测、模糊搜索和目录级快速收藏。
6. 设置、弹窗、右键菜单的可访问语义和状态反馈不完整。
7. 图标和部分资源依赖未固定的远程 CDN，离线和隐私边界不稳定。

## 2. 产品目标

本轮将 Fu 导航收敛为“以导航效率为核心、组件能力可选、数据操作可信”的个人新标签页。

成功结果：

- 在 1024×768 及以上窗口中，无滚动即可使用搜索并打开首页常用网站。
- 搜索 Provider、筛选、锁定、拖拽、嵌套编辑的行为与界面文案完全一致。
- 凭据不会进入同步配置、云端备份或导出文件。
- 多上下文同时写入时，删除不会因合并而复活；导入和恢复可预览、可回滚。
- 新用户可在“导入书签、使用演示模板、从空白开始”之间明确选择。
- 数百条网站仍可通过模糊/拼音搜索、批量操作、重复检测和目录树快速管理。
- 核心界面满足键盘操作、可访问名称、焦点管理和 WCAG AA 对比度要求。
- 断网时核心导航、分组图标和编辑操作仍然可用。

## 3. 方案比较与决策

### 方案 A：渐进式加固，保留现有架构（采用）

保留纯 ES Module、现有 `Core`、布局与设计 token，先抽出可测试的配置、搜索、树操作和导入模块，再逐阶段替换原有逻辑。

优点：迁移风险低，每个阶段都能独立验收，兼容现有用户数据。缺点：实施期间新旧接口会短期共存，需要严格的兼容层和回归测试。

### 方案 B：先重写数据层，再恢复全部 UI

一次性建立全新状态仓库、事件总线和同步协议，再让页面迁移到新接口。

优点：长期边界更清晰。缺点：本项目没有既有自动化测试，重写窗口过大，容易同时破坏书签同步、弹窗和新标签页。

### 方案 C：全面重构为框架应用

迁移到 React/Vue、构建系统和完整 E2E 工具链。

优点：生态和组件化能力强。缺点：与本轮产品目标无直接关系，增加依赖、构建和扩展 CSP 风险，不符合 YAGNI。

决策：采用方案 A。本轮不更换框架、不重做品牌、不推翻 `DESIGN.md`，只对服务于产品闭环的模块边界做定向拆分。

## 4. 全局约束

- 继续使用 Manifest V3 和原生 ES Modules，不引入运行时框架。
- 自动化单元测试使用 Node.js 内置 `node:test`，不新增测试运行时依赖。
- 保持 Chrome 与 Edge 的“加载已解压”安装方式。
- 保持现有配置向前兼容；迁移必须幂等，失败时保留原配置。
- 深色、浅色、自动主题均保持可用。
- 所有 UI 改动遵守 `DESIGN.md`；缺少规则时先更新设计规范。
- 页面和弹窗不得依赖联网才能完成导航、搜索、分组和编辑。
- 新增远程服务或第三方代码必须固定版本、记录许可证并在 README 披露。
- `eval.md` 是完成的唯一定义；判据只增不删不改，只更新 `passes`。
- 开发执行完全自主，不设置人工审阅、验收或批准闸门；实现 agent 自行完成浏览器走查、证据留存和 eval 更新。
- 已有场景模式、七步引导、frecency 常用算法、Provider action、使用统计、本地 Inter 字体和 CI 语法闸门必须保留。

## 5. 目标架构与模块边界

### 5.1 配置域

新增纯逻辑模块：

- `shared/config-schema.js`：默认配置、迁移、结构校验和规范化。
- `shared/config-secrets.js`：从配置提取/注入本机凭据，生成安全导出和云备份载荷。
- `shared/sync-policy.js`：本机权威策略、popup 增量操作、删除保护和显式恢复差异。
- `shared/config-history.js`：本机快照的创建、轮换和恢复。

同步配置升级到 schema version 3：

```js
{
  version: 3,
  revision: 0,
  savedAt: 0,
  settings: {},
  groups: []
}
```

`revision` 只用于判断显式导入/恢复的基线差异，不允许触发后台远端覆盖。本机新标签页、popup 和 service worker 之间通过带唯一 `opId` 的增量操作同步；操作日志在本机确认消费后清理。删除操作优先于同会话内更早的新增/编辑，重放同一 `opId` 必须幂等。

WebDAV 用户名、密码和 Google OAuth 临时凭据只保存在 `chrome.storage.local` 的独立键中；预览环境只保存在独立 localStorage 键中。它们不得进入 `config`、`chrome.storage.sync`、导出 JSON 或云备份 JSON。

### 5.2 导入、恢复与同步域

所有外部配置先经过同一流水线：解析 → schema 校验 → 迁移副本 → 差异摘要 → 用户确认 → 创建本机快照 → 应用 → 保存。

差异摘要至少包含：新增、更新、删除、重复、无效条目和设置变化。导入失败不修改当前配置。最近五份快照保存在本机，可在设置中恢复。

`chrome.storage.local` 永远是当前设备的唯一权威。`chrome.storage.sync` 只在本机没有配置的新设备上引导一次，之后不响应跨设备推送。WebDAV/Google Drive 不后台拉取；用户显式恢复时才读取远端，显示差异摘要并提供“合并副本、保留本机、使用云端”三种选择。任何选择应用前都创建本机快照。

### 5.3 导航树域

新增 `shared/tree.js`，统一实现：递归查找、父容器定位、移动、删除、计数、遍历和循环保护。首页、分组页、文件夹页、编辑弹窗、拖拽、弹窗收藏和书签同步不得再各自维护不同的树遍历逻辑。

移动约束：

- 网站可以移动到任意分组或深度不超过 2 的文件夹。
- 文件夹可以在允许深度内重排，但不能移动到自身或后代。
- 锁定状态不产生任何拖拽数据，也不显示抓取光标或编辑提示。

### 5.4 搜索域

`settings.askProvider` 是唯一 Provider 状态；旧 `searchEngine` 仅作为迁移来源，迁移后不再读写。

首页搜索框规则：

- 切换 Provider 只切换目标，不自动提交已有内容。
- 只有 Enter 或发送按钮提交。
- 分组/文件夹页输入框只筛选当前内容，Enter 不触发外部搜索。
- AI Provider 需要复制文本时，在当前页先显示持久反馈，再打开目标页；反馈不能只依赖即将失焦的 Toast。

新增 `shared/search-index.js`，提供网站、分组、文件夹和操作的统一检索。支持中文直接匹配、拼音全拼/首字母、URL/备注/别名匹配和拉丁字符容错模糊匹配。索引在配置变化时增量重建。

### 5.5 UI 状态域

编辑状态统一由 `core.editing` 控制，并同步到 `body.editing`。锁定、编辑按钮、拖拽属性、帮助文案、右键菜单和卡片光标必须由同一状态派生。

新增统一状态模型：

```js
{
  sync: { state: "idle|saving|synced|local-only|conflict|error", message: "", at: 0 },
  permission: { bookmarks: "unknown|granted|denied", identity: "unknown|granted|denied" },
  onboarding: { completed: false, weatherConsent: false }
}
```

同步状态可在设置诊断区长期查看，不只显示瞬时提示。

## 6. P0 范围：正确性、安全与首屏

### P0.1 交互正确性

- 修复 Provider 切换自动提交。
- 设置页 Provider 与首页统一。
- 分组/文件夹筛选保持本地语义。
- 锁定状态彻底禁止拖拽和编辑提示。
- 使用统一树模块修复嵌套项目移动和删除。
- 文件夹页与分组页显示真实的顶层项数、网站总数和子文件夹数。

### P0.2 数据安全

- 凭据本机化并从导出、同步和云备份中剔除。
- 保存和云同步使用递归版本合并与墓碑。
- 导入、云恢复和本地恢复统一使用校验、预览、快照、回滚。
- 存储超限时显示可持续查看的本机保存状态和处理建议。

### P0.3 首页首屏

首页优先级固定为：搜索 → 常用网站 → 可选组件。时钟是辅助信息，不再决定首屏高度。

- 视口高度小于 820px 时启用紧凑首页：时钟缩小，问候/日期合并，组件行紧凑。
- 1024×768 下搜索和至少 8 个常用网站无需滚动可见。
- 侧栏在宽度不大于 1100px 时默认使用折叠态，但尊重用户显式展开操作。
- 硬件监控组件仅在用户配置后显示。
- 组件允许在设置中启用、停用和排序。

## 7. P1 范围：首次使用、规模化管理与可访问性

### P1.1 首次使用

首次安装显示三选一引导：

1. 导入浏览器书签。
2. 使用演示模板。
3. 从空白开始。

演示模板必须带“演示数据”标识，并提供一键清空/替换。天气默认不请求 IP 定位；用户启用后显示数据来源说明并记录同意。书签和身份权限在开启对应功能时请求，拒绝后产品仍可继续使用。

### P1.2 规模化书签管理

新增“书签库”管理面板：

- 全局搜索、拼音/模糊匹配和条件筛选。
- 多选、全选当前结果、批量移动、批量删除。
- 重复网址聚类、保留/合并/忽略。
- 失效链接筛选和集中处理。
- 标签、别名和备注的编辑与检索。
- 导入差异和重复处理复用同一套表格与操作模型。

URL 规范化忽略协议大小写、默认端口、尾斜杠和纯跟踪参数；是否忽略 `www`、业务查询参数和 hash 由用户在重复组中确认，避免误合并。

### P1.3 工具栏弹窗

- 使用可展开的分组/文件夹树选择保存位置。
- 显示最近三个保存位置并记住上次位置。
- 保存前提示精确重复和可能重复。
- 保留“快速保存”，高级编辑可设置备注、常用、面板打开和自定义图标。
- 新标签页、弹窗和后台角标共用同一 URL 规范化函数。

### P1.4 可访问性

- 所有表单标签与控件建立程序化关联。
- 所有图标按钮拥有可访问名称和至少 32×32px 命中区。
- 对话框使用 `aria-labelledby`，实现焦点锁定、Escape 关闭和焦点恢复。
- 自定义菜单支持方向键、Home/End、Enter/Space 和 Escape。
- Provider、侧栏、文件夹树等展开控件提供 `aria-expanded`。
- Toast、同步、导入和权限结果通过 live region 宣告。
- 深浅主题正文和交互文字达到 WCAG 2.1 AA。

## 8. P2 范围：离线、设置、工作区与视觉收口

### P2.1 离线资源与隐私

- 核心 Lucide 图标和分组图标随扩展打包。
- 品牌图标优先使用浏览器 favicon、本机缓存或稳定固定版本源；失败时显示本地字母图标。
- 移除未使用的 `v1.hitokoto.cn` 权限和无实际用途的字体预连接。
- README 的权限与网络请求表必须与 manifest 和源码一致。
- `bookmarks`、`identity` 等可选能力在平台允许时迁移为运行时授权。

### P2.2 设置与诊断

设置重组为“常用、数据与同步、外观、组件、高级与诊断”。默认只展开常用区。

诊断区显示：配置大小、sync 使用情况、最后保存、最后云备份、冲突状态、已授权能力、本机 Agent 状态和最近错误。提供复制诊断信息按钮，输出中不得包含 URL 中的凭据、密码、token 或网站清单。

### P2.3 场景模式（工作区）管理

沿用现有“场景模式”作为工作区模型，不再创建第二套 workspace 数据。管理界面支持创建、重命名、排序、归档、恢复和删除。删除前显示受影响分组数；删除模式只解除分组归属，不删除任何分组。

命令面板保留快速切换和创建入口，侧栏显示当前模式及可发现的管理入口。旧 `group.page/activePage/privacy` 只作为迁移来源，不恢复为运行时模型。

### P2.4 响应式与视觉细节

- 宽度不大于 760px 时侧栏改为抽屉，不占据页面顶部整块空间。
- 分组和文件夹页面根据内容量限制最大宽度，少量卡片不铺出大面积空白。
- 文件夹卡片始终显示网站和子文件夹计数。
- 背景图模式根据主题和图片亮度使用可配置 scrim；小字号元信息仍满足对比度要求。
- 视觉变化保持当前近单色、单一强调色、低动效设计，不增加营销式 Hero、渐变标题或装饰性动画。

## 9. 错误处理

- 所有存储、导入、云同步和权限错误返回结构化结果 `{ ok, code, message, details? }`。
- 用户可恢复的错误必须给出下一步操作；不可恢复错误保留诊断记录但不暴露敏感信息。
- 外部请求失败不阻塞核心导航渲染。
- 配置迁移失败时加载原配置的只读副本，并提供导出原始数据入口。
- 批量操作在执行前创建快照；部分失败时显示成功/失败数量并允许重试失败项。

## 10. 兼容与迁移

- v2 配置首次加载时迁移到 v3，并保留旧字段读取兼容一个版本。
- `searchEngine` 的有效值迁移到 `askProvider`；之后删除运行时双写。
- 旧 `settings.cloud.user/pass` 提取到本机 secret storage 后立即从配置删除。
- 迁移前自动保存原始配置快照；迁移函数重复执行不得改变结果。
- popup、background service worker 和 newtab 使用同一 schema、tree、URL 与 storage API。
- 继续维持 `chrome.storage.local` 唯一权威和 `fn_inbox` 增量交付，不恢复旧版 `_mergeIn/cloudPull` 路径。

## 11. 测试与验收策略

### 自动化

- Node 内置测试覆盖 config schema、secret 清洗、本机权威同步策略、增量操作幂等与删除优先、树移动/删除、URL 规范化、模糊搜索和导入差异。
- 静态检查覆盖敏感字段不得进入导出/云载荷、manifest 未使用权限、远程 `@latest/@main` 引用和无名称图标按钮。

### 组合与端到端

至少覆盖：

1. 新安装 → 选择导入书签 → popup 保存到嵌套文件夹 → 新标签页实时出现 → 模拟远端更新后仍存在。
2. 两个本机上下文并发：一个删除嵌套网站，一个编辑其他网站 → inbox 操作兑现后删除项不复活，编辑项保留。
3. Provider 切换 → 输入保留但不提交 → Enter 后仅提交一次。
4. 1024×768 深浅主题：首页搜索和常用区无需滚动可见。
5. 设置 WebDAV 凭据 → 云备份与导出 → 两份 JSON 均无密码、token 和本机 secret。

所有验收项及具体命令记录在根目录 `eval.md`。

## 12. 明确不做

- 不迁移到 React、Vue 或其他前端框架。
- 不引入账号系统、服务端数据库或遥测平台。
- 不自动删除失效链接或自动合并可能重复的网站。
- 不开放任意 HEX 强调色。
- 不增加超过两级的文件夹深度。
- 不保证所有品牌图标完全离线，只保证核心操作与可识别的本地 fallback。
- 不在本轮上架 Chrome Web Store。

## 13. 发布顺序

1. P0 正确性与数据安全；完成后旧用户可无损迁移。
2. P0 首页首屏；保持所有现有表面视觉一致。
3. P1 首次使用、书签库、popup 与可访问性。
4. P2 离线、设置诊断、工作区与响应式收口。
5. 全量执行 `eval.md`，任何失败项都阻止“完成”结论。
