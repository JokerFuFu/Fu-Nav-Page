# 原收藏目录结构恢复设计

日期：2026-08-09

状态：已批准。用户要求优先按浏览器原目录结构拆分；无法匹配的现有条目需归类，禁止继续平铺。用户同时要求全程自主执行，不设置人工查看或批准门槛。

## 1. 问题修正

上一版恢复链路正确找回了网址和元数据，但 `mergeBookmarkFolder` 把浏览器 `Fu 导航` 文件夹的全部后代网站展平到一个分组根层。截图中的“顶层 255 项”证明网址数量恢复了，目录语义没有恢复。本次不是重新抓取网址，而是对已恢复的扁平数据执行一次结构迁移。

## 2. 方案选择

评估三种方案：

1. **原样重建嵌套目录（采用）**：浏览器文件夹转为导航 `type: 'folder'` 节点，网站回到原路径。保真度最高，不需要猜测。
2. **一级文件夹拆成侧栏分组**：查找更直观，但改变原根目录结构，根层网站也需要另设分组。
3. **按名称与域名自动分类**：可处理完全扁平的源数据，但存在误分类，且不应覆盖浏览器已经提供的目录事实。

项目现有树模型和 Fusion 布局以两级文件夹为合法配置上限：侧栏展示顶层文件夹，第二级文件夹在页面内继续进入。因此方案 1 不需要新增 UI 组件；浏览器第三级及以后路径需要按第 3 节的确定规则折叠，而不能写入非法配置。

## 3. 数据转换

在 `shared/bookmark-recovery.js` 新增纯函数：

```js
rebuildBookmarkFolderStructure(config, sourceFolder, options)
// -> { config, changed, total, folders, reused, added, unclassified, groupId }
```

转换规则：

- 克隆输入配置，不原地修改。
- 查找或创建与源根目录同名的导航分组。
- 浏览器前两级文件夹转换为 `{ type:'folder', id, name, icon:'folder', items }`，保持兄弟顺序与父子关系。
- 浏览器第三级及以后不能继续生成子文件夹，改为在第二级生成带完整相对路径的兄弟目录，例如 `前端 / 框架 / React`；目录内网站仍按原路径分开，不回退为根层平铺。
- 如果浏览器源根目录完全没有文件夹，则认定原结构已经不可恢复，才启用确定性自动归类。分类顺序固定为：`网络与设备`、`AI 与效率`、`开发工具`、`设计创意`、`邮箱通讯`、`影音娱乐`、`财经购物`、`学习阅读`、`其他`。规则只依据名称、URL 与私网地址特征，不联网、不调用 AI；现有网站对象仍按 URL 复用。
- 对网站使用 `normalizeUrl(url, 'strict')` 去重。目标分组中已有同 URL 条目优先复用完整对象，保留稳定 ID、用户名称、备注、标签、图标、收藏状态和访问统计，只改变其容器位置。
- 浏览器源中新 URL 创建导航网站条目；源目录中的重复 URL 只保留首次出现的位置。
- 目标分组中没有出现在浏览器源目录的现有网站不得删除，统一移动到根层 `未归类` 文件夹。
- 迁移生成的文件夹保存 `bookmarkSourceId`；重复执行时复用已有文件夹 ID，保证结构迁移幂等。
- 无源文件夹或源内没有有效网站时保持配置不变。

## 4. 自动迁移

Core 新增 `recoverOriginalBookmarkStructure()`，在原网址恢复之后运行：

- 仅扩展环境、书签 API 可用且 `chrome.permissions.contains({permissions:['bookmarks']})` 已授权时执行。
- 使用新的 `settings.bookmarkStructureRecoveryV327` 标记，确保已经执行过上一版扁平恢复的用户仍会进入本次结构迁移。
- 找到内容最多的同名 `Fu 导航` 浏览器文件夹后，先保存 `bookmark-structure-recovery` 快照，再替换配置并持久化。
- 禁止调用 `chrome.permissions.request`，禁止开启双向同步，禁止在本次迁移中反向导出浏览器书签。
- 失败时保留当前配置且不写成功标记，以便下次启动重试。

## 5. 兼容性

- 新安装或尚未恢复的用户：同一次启动先补齐缺失 URL，再重建目录。
- 已经完成扁平恢复的用户：旧标记不阻止新结构迁移，已恢复的稳定网站 ID 和元数据被复用。
- 已经是结构化数据的用户：函数复用文件夹和网站 ID，第二次执行 `changed === false`。
- 超过两级的浏览器目录：前两级保持原样，后续层级折叠进第二级目录名称，确保 `validateConfig` 仍通过。
- 完全扁平的浏览器源目录：自动生成稳定分类文件夹；分类文件夹使用 `auto:<category>` 来源标识，重复执行复用文件夹 ID。
- 原目录根层网站仍留在分组根层，这是对原结构的忠实表达；只有来源不明的额外网站进入 `未归类`。
- 不修改首页居中、分组页、设置、popup 或现有树深度浏览能力。

## 6. 验收

- 单元测试覆盖两级目录、超过两级的路径名折叠、完全扁平源的自动归类、兄弟顺序、根层网站、已有扁平条目回填原路径、元数据/ID 保留、重复 URL、未归类和幂等重放。
- Core 静态测试确认新版本标记、`permissions.contains` 与禁止 `permissions.request`。
- 真实扩展 E2E 预置已完成旧扁平恢复的配置，再注入带子目录的浏览器 `Fu 导航` 树；启动后检查文件夹节点、深层网站路径、网站 ID/备注、总网站数和第二次启动稳定性。
- 全量 `npm test`、`npm run verify:static`、`npm run verify:e2e` 与 `git diff --check` 全部 exit 0，新增 eval 判据才能翻绿。
